# 04 插件开发

插件是内核唯一的一等扩展点：**一个 id、一个标题、一个渲染函数**。内置面板与业务插件使用完全相同的 API。

## 1. 最小示例（原生 DOM）

```ts
import { definePlugin, h } from '@rinova/devtools'

const orderPlugin = definePlugin({
  id: 'orders',
  title: '订单',
  icon: 'layers',      // lucide 图标名，见 IconName
  order: 20,           // 侧栏排序，数字小的靠前
  subtitle: '最近 20 条订单',
  badge: () => 3,      // 侧栏角标，返回 null 隐藏

  render(container, ctx) {
    const list = h('div', { style: { padding: '12px' } })
    container.appendChild(list)

    const load = async () => {
      const rows = await fetch('/api/orders').then((r) => r.json())
      list.replaceChildren(
        ...rows.map((row) => h('div', { class: 'rdt-store-row', text: row.id }))
      )
    }

    void load()
    ctx.onDispose(() => list.remove())
  }
})
```

注册：

```ts
createDevtools({ plugins: [orderPlugin] })
// 或运行时
devtools.registerPlugin(orderPlugin)
```

## 2. DevtoolsPlugin

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| `id` | `string` | 唯一；与内置面板同 id 时覆盖内置 |
| `title` | `string` | 侧栏 tooltip 与内容区标题 |
| `icon` | `IconName` | 仅支持按需引入的 lucide 图标表，未知值回退为圆点 |
| `order` | `number` | 默认 100；`settings` 固定吸底 |
| `subtitle` | `string \| () => string` | 标题下说明；函数会在面板激活与数据变化时重新求值 |
| `badge` | `() => number \| string \| null` | 侧栏角标 |
| `enabled` | `boolean \| () => boolean` | 注册时求值；为 false 的插件不进入侧栏（内置面板同样适用） |
| `render` | `(container, ctx) => void` | 首次注册时调用一次，之后容器常驻 |
| `refresh` | `() => void` | 预留，供壳层主动刷新 |

**生命周期**：`render` 在 `registerPlugin` 时立即执行；切换面板只控制容器显隐。需要清理的资源（定时器、订阅、子应用）用 `ctx.onDispose` 注册。移除插件或 `destroy()` 时统一执行。

## 3. PluginContext

| 成员 | 说明 |
| --- | --- |
| `container` | 插件独占容器（绝对定位、占满内容区） |
| `root` | ShadowRoot，可用于挂自定义浮层 |
| `app` | `{ name, version }` |
| `values` / `getValue(key, fallback)` | 当前配置快照 |
| `setValue(key, value)` | 以 `program` 身份写入配置 |
| `onChange(handler)` | 监听配置变化，返回取消函数（自动登记 dispose） |
| `on(event, handler)` | 监听任意内核事件 |
| `emit(event, payload)` | 自定义事件，其他插件/宿主可订阅 |
| `storage.get/set/remove` | 以插件 id 为命名空间的持久化 |
| `network.entries/clear/replay/capturing/setCapturing` | 网络采集 |
| `toast(text, tone)` | 面板内轻提示（success / error / info / warning） |
| `copy(text)` | 复制并自动提示，返回是否成功 |
| `onDispose(fn)` | 注册清理函数 |
| `devtools` | 内核实例，谨慎使用 |

## 4. 用 Vue 写插件

插件容器是普通 DOM，直接挂一个 Vue 子应用即可；**别忘记卸载**。

```ts
import { createApp, h as vh } from 'vue'
import { definePlugin } from '@rinova/devtools'
import OrderPanel from './OrderPanel.vue'

export const orderPlugin = definePlugin({
  id: 'orders',
  title: '订单',
  icon: 'layers',
  render(container, ctx) {
    const app = createApp({
      render: () => vh(OrderPanel, { token: ctx.getValue('token', '') })
    })
    app.mount(container)
    ctx.onDispose(() => app.unmount())
  }
})
```

React 同理：

```tsx
import { createRoot } from 'react-dom/client'

render(container, ctx) {
  const root = createRoot(container)
  root.render(<OrderPanel token={ctx.getValue('token', '')} />)
  ctx.onDispose(() => root.unmount())
}
```

## 5. 样式

- 所有内容在 Shadow DOM 内，宿主样式不会影响你，你的样式也不会泄漏。
- 推荐使用内核 CSS 变量：`var(--rdt-text)`、`var(--rdt-surface)`、`var(--rdt-border)`、`var(--rdt-accent)`、`var(--rdt-mono)`。
- `h / button / tag / empty / segmented` 是**便利工具**，它们依赖 `rdt-*` class；class 名称不承诺稳定，生产插件建议自带样式，只依赖 CSS 变量。
- 不要在插件里 `document.body.appendChild` 浮层——它会在 shadow 之外，主题变量失效；用 `ctx.root` 或容器内绝对定位。

## 6. 事件契约

| 事件 | 用途 |
| --- | --- |
| `plugin:activate` | `{ id }`，切到本面板时做一次懒刷新（存储面板即用此机制） |
| `config:change` | 配置变化 |
| `network:change` | 采集列表变化（开始/结束/清空） |
| `log:change` | 日志变化 |
| `ui:theme` / `ui:dock` / `ui:width` | 设置变化 |
| `actions:change` | 快捷操作增删 |

自定义事件是自由命名空间，例如 `orders:refresh`；注意避免与内核事件重名。

## 7. 快捷操作

动作不是面板，而是"一键执行"，出现在 `快捷操作` 面板中。

```ts
actions: [
  {
    id: 'copy-token',
    label: '复制 TOKEN',
    description: '从配置读取 token 字段',
    icon: 'key',
    run: async (ctx) => {
      await ctx.copy(String(ctx.getValue('token', '')))
    }
  },
  {
    id: 'clear-cache',
    label: '清空演示缓存',
    tone: 'danger',
    confirm: '确认清空？', // 第一次点击变为「确认执行？」
    run: (ctx) => {
      localStorage.removeItem('demo-draft')
      ctx.toast('已清空', 'success')
    }
  }
]
```

运行时注册：`devtools.registerAction(action)`，返回注销函数。同 id 覆盖。

## 8. 约定与限制

- `render` 抛错不会影响内核，容器会显示错误信息，控制台有完整堆栈。
- 插件一旦注册即渲染，**不要在 render 里做昂贵的一次性初始化**；需要懒加载时监听 `plugin:activate`。
- 侧栏图标不支持运行时从字符串动态加载全部 lucide（会拖垮体积）；新增图标请在 `icons.ts` 登记。
- 网络面板、日志面板的数据源是全局采集器，插件可以通过 `ctx.network` 读取，但不要直接替换它们。
