# 07 决策与路线图

## 1. 关键决策（ADR）

### ADR-001 内核用原生 DOM + Shadow DOM，而不是 Vue 组件

**背景**：参考实现是 1600 行 Vue 单文件组件，绑定路由、用户 store、登录接口与 Element Plus。

**决定**：内核只用 DOM API，所有 UI 放进 Shadow DOM。

**理由**：

- 同一份能力可以给 Vue / React / Svelte / 原生页面使用，不需要重写。
- 样式隔离是调试工具的硬需求（宿主 reset 会把面板改成灾难）。
- 适配器变薄后，框架升级不会影响内核。

**代价**：不能用 Vue 的模板与响应式，内置面板用命令式 DOM 编写；需要自建 `h` 等少量工具。实测六个面板的代码量与可维护性可接受。

### ADR-002 插件 API 采用 `render(container, ctx)`，不做配置 DSL

**决定**：插件拿到容器与上下文，自行渲染。

**理由**：调试面板的形态差异极大（表格、图表、iframe、子应用），任何 DSL 都会在第三个业务插件处失效。`render` 的上限就是 DOM 的上限。

**代价**：插件作者需要自己处理更新；内核不提供虚拟 DOM。对复杂插件，推荐在容器内挂 Vue / React 子应用。

### ADR-003 不引入 UI 组件库

**决定**：按钮、输入框、开关、下拉、标签等全部手写，样式用 Less + CSS 变量。

**理由**：公共调试包不能把 Element Plus（或任何 UI 库）塞进使用方产物；Shadow DOM 内的组件库样式也需要额外适配。

**代价**：交互细节（下拉键盘导航、焦点管理）需要自己维护，当前为"够用"级别。

### ADR-004 图标使用 lucide，并显式登记

**决定**：`lucide` 具名导入 + `icons.ts` 名称表，插件通过字符串选择图标。

**理由**：tree-shaking 友好（当前 38 个图标），插件作者不需要额外依赖图标库，也不会出现风格混搭。未知名称回退为圆点，不抛错。

### ADR-005 网络采集补丁全局 fetch/XHR

**决定**：挂载时包装全局函数，`destroy()` 还原。

**理由**：业务无需改一行请求代码；比 Service Worker 方案侵入性小。

**代价**：单实例约束；挂载前的请求无法记录；与其它同样补丁 fetch 的库（如某些 Mock 工具）可能叠加，需注意顺序。

### ADR-006 配置值持久化优先于代码默认值

**决定**：`localStorage` 中的值覆盖 `options.values` / `defaultValue`。

**理由**：调试工具的语义是"我上次调好的环境"，不应因为发版改默认值而被重置。需要重置时用"恢复默认"。

### ADR-007 不内置账号管理 / Mock / 埋点

**决定**：快捷登录、MockServer、录制回放留在业务侧，通过插件或动作接入。

**理由**：这些能力与登录协议、后端网关强耦合，内置会把内核变成第二套业务框架。参考实现的快捷登录账号表本质是业务数据管理，不适合公共包。

## 2. 当前状态（v0.1）

已完成：

- 框架无关内核、Shadow DOM UI、主题（深/浅/自动）、三向停靠、拖拽与吸附、快捷键。
- 六个内置面板：配置、网络、存储、日志、快捷操作、设置。
- Vue 3 适配器（插件、`useDevtools`、组件）。
- 两个可运行示例：Vue 3 演示、纯 DOM 演示。
- 单元测试 **122 条**（core 117 + vue 5），语句覆盖率 86.27%、行 89.19%；另有 15 组浏览器实机用例与生产隔离脚本，详见 `docs/08-测试计划与用例.md`。

未发布 npm，版本号 `0.1.0`，API 仍可能在 0.2 前调整。

## 3. 已知问题

按影响排序：

1. **多实例不安全**：重复创建会叠加补丁。文档已声明，后续可加全局锁。
2. **底部停靠高度不持久**：拖拽可改，但刷新恢复默认；宽度已持久化。
3. **网络列表全量重绘**：上限 200 条时可用，高频请求下会抖；0.2 改虚拟列表 + 增量插入。
4. **SSE / 流式响应体为空**：clone 读取 4 秒超时即放弃。
5. **XHR 请求头缺失**：浏览器不暴露，无法补齐。
6. **Cookie 只展示 name/value**：Domain / Path / Expires / SameSite 无法从 `document.cookie` 读取。
7. **无焦点陷阱**：面板非 modal，Tab 可以走到宿主页面；键盘可用但不是完整的无障碍实现。
8. **文案仅中文，硬编码**：未做 i18n。
9. **插件图标需登记**：不支持任意 lucide 名称动态加载。
10. **响应体截断不可见全文**：超过 200KB 仅标注截断，不能展开全文。

## 4. 路线图

### v0.2（可用性）

- React 适配器 `@rinova/devtools-react`，与 Vue 版 API 对齐。
- 网络列表虚拟化 / 增量渲染，支持 1000 条。
- 请求详情支持"复制为 fetch / axios"。
- 面板宽度、底部高度统一持久化；快捷键可配置。
- i18n（中 / 英），文案集中到字典。
- 焦点陷阱与 `aria` 审计。

### v0.3（调试深度）

- DOM 轮廓检查器（hover 高亮、盒模型、层级）。
- 路由面板（接入方可注册当前路由快照）。
- Mock 面板（请求改写规则，基于 fetch 拦截）。
- 会话录制（rrweb 可选插件，不内置）。
- 插件市场雏形：提供 `definePlugin` 模板与脚手架。

### 暂不做

- 组件树 / 性能面板（与框架 Devtools 重叠，投入产出比低）。
- 远程调试与云端同步（涉及账号、权限、数据合规）。
- 生产环境监控（定位是开发调试，不是 APM）。
