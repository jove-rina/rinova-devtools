# 01 产品定义

## 1. 一句话

`@rinova/devtools` 是一个**框架无关**的前端调试面板：一行代码接入任意 Web 应用，提供环境配置、网络、存储、日志与快捷操作，并允许业务方以插件形式扩展自己的调试能力。

## 2. 为什么不是再写一个 Vue 组件

`df-erp-static` 的 `DevTools` 证明了两件事：

1. 业务开发真正高频需要的不是"再开一个浏览器 DevTools 窗口"，而是**贴着业务的环境配置、快捷切号、Mock 开关、调试开关**。
2. 把一个 1600 行的 Vue 组件直接复制到下一个项目，会把路由、用户 store、登录接口、Element Plus 一起带过去，无法复用。

所以本项目的边界是：

- **内核只认 DOM**：不引入 Vue / React / Element Plus / Tailwind，不与任何状态库耦合。
- **能力以插件为单元**：内置面板是第一方插件，业务插件与它们平级。
- **适配器只做生命周期与响应式桥接**：Vue 包不超过 150 行，React、Svelte 同理。

## 3. 目标用户

- 需要在多套环境（本地 / 测试 / 灰度 / Mock）之间切换的前端与测试。
- 需要查看"这次点击到底发了什么请求"的产品、设计、后端。
- 想把团队内部工具沉淀成公共包的技术负责人。

## 4. 核心体验

| 能力 | 说明 |
| --- | --- |
| 悬浮球 | 常驻页面右下角，可拖拽、自动吸附边缘，位置本地记忆 |
| 快捷键 | 默认 `alt+shift+d`，输入框内不会被无修饰键误触 |
| 面板 | 右侧 / 左侧 / 底部三向停靠，宽度可拖拽并记忆 |
| 配置 | schema 驱动的字段（下拉 / 文本 / 数字 / 开关），改动即时生效并持久化 |
| 网络 | 补丁 `fetch` 与 `XMLHttpRequest`，记录状态、耗时、请求/响应体，可复制 cURL、重放 |
| 存储 | 查看和编辑 localStorage / sessionStorage，查看与删除 Cookie |
| 日志 | 捕获 console 与未捕获异常，按级别过滤、搜索、复制 |
| 快捷操作 | 接入方注册的动作（复制 token、切 Mock、清缓存……），支持二次确认 |
| 设置 | 主题（深/浅/跟随系统）、停靠方向、宽度、悬浮球复位、清理本地数据 |
| 插件 | 任意技术栈通过 `render(container, ctx)` 渲染自己的调试面板 |

## 5. 明确不做（v0.1）

- 不做 Vue Devtools / React Devtools 的组件树、性能面板替代品。
- 不做远程调试、多端同步、埋点上报；**无任何网络外发**。
- 不做"生产环境全量开启"：默认由接入方用 `enabled` 控制。
- 不做 UI 组件库，也不导出通用组件；`h / button` 只是插件作者的轻量工具。
- 不做拖拽式面板编排（v0.2 再评估）。

## 6. 与参考实现的关系

`df-erp-static/src/components/DevTools` 的能力被吸收为：

| 参考能力 | 本项目的落地 |
| --- | --- |
| 悬浮球 + 径向菜单 + 扇形面板 | 悬浮球 + 侧栏 + 停靠面板（键盘可达，窄屏可用） |
| 网关 / 灰度 / Token | `config` 面板的 schema 字段（任意项目自定义） |
| AB / UE / 接口调试开关 | `switch` 字段，业务通过 `getValue()` 读取 |
| 快捷登录账号管理 | 未内置；账号是业务语义，用插件或 action 实现 |
| Mock / 录制 | 未内置；通过配置字段 + 网络面板配合第三方 MockServer |
| 主题切换 | 内置深/浅/跟随系统 |

产品方向刻意从"炫技式径向菜单"转向"可长期维护的调试台"：信息密度更高、键盘可用、窄屏不残废、任何框架都能接。

## 7. 成功标准

- 新项目接入 ≤ 10 行代码，构建产物不进入生产依赖路径（`enabled: false` 或按需 import）。
- 业务新增一个调试面板 ≤ 40 行代码，不需要了解内核实现。
- 面板在 1440px、1024px、390px 三种宽度下无横向滚动、无遮挡关键操作。
- 核心包 gzip < 35KB（当前 30.5KB，含 icons 与样式）。
